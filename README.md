# Steam Game Curator

> **자연어로 질문하면 정형 조건과 실제 유저 리뷰(RAG)를 결합하여 맞춤 게임을 추천하고 평판을 분석해주는 AI 에이전트 웹앱**

---

## 핵심 요약 (Key Highlights)

* **하이브리드 추천 엔진**: 정형 조건(가격/장르/할인)은 **Pandas & Chroma `where` 필터**로, 취향/감성/평판은 **8,402건의 한국어 유저 리뷰 벡터 검색(RAG)**으로 동시 해결합니다.
* **자율적인 Function Calling**: LLM(`gemini-3.7-flash`)이 사용자 질문의 의도에 따라 5가지 전용 툴을 자동 선택하고 최대 4턴에 걸쳐 자율 실행합니다.
* **철저한 환각(Hallucination) 방지**: Pydantic 기반 인자 엄격 검증 + 경로별 유사도 임계값(Threshold) 게이트 + **근거 리뷰 원문/플레이타임 투명 노출** 체계를 갖췄습니다.
* **검증된 검색 성능**: 게임 상점 설명만 검색했을 때 대비 **정밀도(P@5) 71% 향상 (0.320 → 0.547)**, **Hit@5 100% 달성**을 실측으로 증명했습니다.

```
┌──────────────┐      ┌─────────────────────────┐      ┌─────────────────────────┐
│  사용자 질문  │ ───► │  LLM (Function Calling) │ ───► │  Pydantic 인자 검증     │
└──────────────┘      └─────────────────────────┘      └────────────┬────────────┘
                                                                    │ 통과 시
                      ┌─────────────────────────┐      ┌────────────▼────────────┐
                      │ Streamlit 대시보드 / 챗봇 │ ◄─── │  Chroma 벡터 DB / CSV   │
                      │  (근거 리뷰 및 Trace 노출)│      │  (리뷰 집계 & 하이브리드)│
                      └─────────────────────────┘      └─────────────────────────┘
```

## 프로젝트 배경 및 목표 (Problem & Solution)

스팀의 인기 게임들은 장르 태그(`액션`, `인디` 등)만으로는 게임의 실제 플레이 느낌과 품질을 파악하기 어렵습니다.

* **정형 필터링의 한계**: "3만원 이하 액션 게임"은 조건 검색으로 찾을 수 있지만, *"친구랑 둘이 낄낄대며 할 만한 협동 게임"*은 찾지 못합니다.
* **상점 설명의 한계**: 개발사가 작성한 상점 소개글에는 *"핵이 많은지"*, *"최적화가 엉망인지"*, *"진짜 극악의 난이도인지"* 적혀있지 않습니다.
* **해결 방안**: **실제 유저 리뷰 원문 RAG + 정형 메타데이터 하이브리드 필터링**을 결합하여, 조건과 감성 질문을 모두 만족하는 추천 시스템을 구축했습니다.

### 질문 유형별 처리 방식

| 질문 유형 | 질문 예시 | 처리 방식 | 사용 툴 |
|---|---|---|---|
| **정형 조건** | "3만원 이하, 할인 중인 액션 게임 5개" | CSV 메타데이터 필터링 | `search_games_by_filter` |
| **취향 / 감성** | "혼자 조용히 힐링되는 스토리 게임" | 리뷰 벡터 검색 & 상위 리뷰 점수 집계 | `search_games_by_vibe` |
| **하이브리드** | "3만원 이하인데 스토리 감동적인 게임" | Chroma `where` 필터 + 리뷰 벡터 검색 | `search_games_by_vibe` |
| **평판 / 리뷰 질의**| "Counter-Strike 2 요즘 핵 많아?" | 해당 게임의 긍정/부정 리뷰 분리 RAG | `ask_about_game_reviews` |
| **상세 / 비교** | "A 게임과 B 게임 스펙 비교해줘" | 정형 데이터 조회 및 대조 | `compare_games` / `get_game_detail` |

## 빠른 시작 (Quick Start)

### 1. 환경 설정 및 패키지 설치
```bash
cp .env.example .env
uv sync
```
`.env` 파일에 Gemini API 키를 입력합니다:
```ini
GEMINI_API_KEY=your_gemini_api_key_here
GEMINI_MODEL=gemini-3.7-flash
EMBEDDING_MODEL=gemini-embedding-2
```

### 2. 벡터 인덱싱 (최초 1회)
수집된 정형 데이터(`games.csv`, 1,220건)와 리뷰(`reviews.csv`, 8,402건)를 ChromaDB에 인덱싱합니다:
```bash
uv run python -m src.index.index_games     # 약 2분 소요
uv run python -m src.index.index_reviews   # 약 7분 소요
```

### 3. 웹앱 실행
```bash
uv run streamlit run app/streamlit_app.py
```

> **CLI 테스트 및 평가 도구:**
> ```bash
> uv run python -m src.agent.orchestrator       # 터미널에서 대표 4개 질문 대화 테스트
> uv run python -m src.eval.recall              # 15개 평가 문항 벤치마크 (Recall@5 측정)
> uv run python -m src.eval.threshold           # 임계값 및 유사도 분포 측정
> ```

## 핵심 아키텍처 및 실측 결과

실제 수천 건의 API 호출과 벤치마크 측정을 통해 검증된 핵심 설계 포인트입니다.

### 1. 왜 리뷰를 1건 단위(문서 1개)로 분리 저장했는가?
* **게임 단위로 합쳤을 때**: 리뷰 30개를 하나로 합치면 문맥이 평균화되어 정답 유사도(0.45~0.51)가 무관한 질문 점수(0.54)보다 낮아지는 문제가 발생했습니다.
* **1리뷰 1문서 채택**: 개별 리뷰 단위로 임베딩했을 때 정답 유사도가 **0.70~0.75**로 상승하고, 사용자에게 **"추천의 근거가 된 리뷰 원문"**을 투명하게 제공할 수 있게 되었습니다.

### 2. 하이브리드 검색 (Chroma `where` + 벡터)
"3만원 이하인데 스토리 좋은 게임"과 같은 질문은 검색 후 필터링(Post-filtering)하면 상위 100건이 모두 고가 게임일 때 결과가 소실됩니다.
* Chroma의 `where` 메타데이터 조건을 벡터 쿼리와 동시에 전달하여 **단 1회의 검색으로 조건과 감성을 완벽히 만족**시킵니다.

### 3. 듀얼 컬렉션 동적 라우팅 전략
* 리뷰가 풍부한 게임(299개)과 상점 설명만 존재하는 게임(921개)이 공존합니다.
* **점수 기반 동적 배정**: `steam_reviews`와 `steam_games` 두 컬렉션을 모두 검색한 후, 최고 유사도가 높은 쪽에 결과 5자리 중 4자리를 우선 배정하고 남은 1자리를 다른 경로로 보완합니다.
* 이 전략을 통해 **Hit@5가 0.867에서 1.000으로, P@5가 0.467에서 0.547로 향상**되었습니다.

### 4. 철저한 환각(Hallucination) 방지 3단계 장치
1. **Pydantic Strict Validation**: LLM이 생성한 함수 인자가 사전 정의된 스키마(존재하는 장르, 유효한 가격 범위 등)를 벗어나면 실행을 즉시 차단하고 LLM에 피드백을 전달하여 재시도합니다.
2. **유사도 임계값(Threshold) 게이트**: 무관한 질문(예: *"세탁기 고치는 법"*)은 임계값(`VIBE_THRESHOLD = 0.65`) 미달 시 LLM 생성 호출 자체를 건너뛰고 "근거 없음"을 반환합니다.
3. **근거 리뷰 및 플레이타임 노출**: LLM 답변 하단에 실제 유저의 플레이타임, 추천 여부, 리뷰 원문을 항상 함께 표기하여 사용자가 직접 신뢰성을 검증할 수 있습니다.

### 5. 긍정 / 부정 리뷰 균형 RAG (`ask_about_game_reviews`)
* 스팀 리뷰의 65% 이상이 긍정적이기 때문에 단순 top-k 검색은 편향을 유발합니다.
* 특정 게임에 대한 질문 시 **긍정 리뷰 상위 2건, 부정 리뷰 상위 2건을 각각 분리 추출**하여 편향 없는 객관적 요약을 제공합니다.

## 검색 성능 평가 (Benchmark)

15개 정답 라벨링 문항(총 91개 정답 게임)을 대상으로 3가지 검색 방식을 동일 문항으로 비교 측정한 결과입니다:

| 검색 방식 | Hit@5 (발견율) | P@5 (정밀도) | R@5 (재현율) | 비고 |
|---|---|---|---|---|
| **1. 게임 설명만 임베딩** | 0.867 | 0.320 | 0.302 | 기존 일반 RAG 방식 |
| **2. 리뷰 집계 경로만 사용** | 0.867 | 0.467 | 0.401 | 리뷰 없는 게임 누락 발생 |
| **3. 실제 하이브리드 경로** | **1.000** | **0.547** | **0.481** | **설명 대비 P@5 +71% 향상** |

### 리뷰 집계 방식이 우세를 보인 주요 문항
* *"스토리가 감동적이고 눈물나는 게임"*: P@5 `0.20 → 1.00`
* *"난이도가 극악인 소울라이크"*: P@5 `0.40 → 0.80`
* *"핵과 부정행위 때문에 짜증나는 게임"*: P@5 `0.20 → 0.60`
* *"무인도 생존 크래프팅"*: P@5 `0.00 → 0.40`
> 개발사가 상점 페이지에 적지 않는 '체감 난이도', '핵 이슈', '최적화' 등의 속성을 유저 리뷰 RAG가 성공적으로 포착했습니다.

## Streamlit 웹 애플리케이션 구성

웹앱은 5개의 독립된 페이지로 구성되어 추천 과정 전체를 투명하게 탐색할 수 있습니다:

```
app/
├── streamlit_app.py              # 메인 홈 (프로젝트 개요 및 시스템 안내)
├── common.py                     # 공통 UI 컴포넌트 및 데이터 캐싱
└── pages/
    ├── 1_데이터.py                # 수집 데이터 규모, 가격/장르/감성 분포 시각화 (Plotly)
    ├── 2_에이전트_설계.py          # 저장 구조, 파이프라인 흐름도, 5개 툴 및 검증 원리
    ├── 3_검색_성능_평가.py         # 15개 문항 성능 비교 벤치마크 결과 및 문항별 분석
    ├── 4_큐레이터_챗봇.py          # 대화형 추천 챗봇 & 사이드바 실시간 Function Calling Trace
    └── 5_게임_상세.py              # 게임별 상세 스펙 및 긍정/부정 분리 리뷰 RAG 질의
```

## 팀 협업 규칙 및 개발 가이드

* **툴 모듈화**: `src/agent/tools/` 내에 독립된 파일로 툴을 추가하면 `registry.py`가 자동으로 감지하여 계약 검증 후 등록합니다.
* **공용 파일 엄격 관리**: 충돌 방지를 위해 `config.py`, `model.py`, `registry.py` 등 공용 파일은 리드가 중앙 관리합니다.
* **단위 검증**: 각 툴 파일 하단의 `if __name__ == '__main__':` 블록을 통해 독립 실행 테스트 후 커밋합니다.
